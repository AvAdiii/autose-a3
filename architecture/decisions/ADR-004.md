# ADR-004: State lives in workflow artifacts, the PR branch and one sticky issue comment; nothing on the PR branch except code and tests

- **Decision area:** D4, state
- **Status:** Accepted (2026-11-21)

## Context

Stages hand over across jobs (build → release → review) and across rounds; a maintainer must be
able to follow a run; and a restarted job should not redo finished work. Candidate stores: files
committed on the PR branch, PR/issue comments, workflow artifacts, the Actions cache, an external DB.

A constraint from ADR-008: the reviewer sees "the repository at the latest commit of the PR". If
`spec.md`, `design.md` or `test_report.md` were committed on the branch, the reviewer would read
the builders' reasoning just by opening the checkout.

## Decision

| State | Store | Why |
|---|---|---|
| Stage artifacts (`spec.md`, `design.md`, `diff.patch`, `test_report.md`, `pr.md`, `review.md`), agent transcripts, `state.json` | **Workflow artifacts**, one per stage per round (`r0-spec`, `r0-design`, ...) | Immutable, linked from the run page, retained 90 days, downloadable by later jobs of the same run; the review job is not given `actions: read`, so it cannot fetch them through the API. |
| Code + tests | **Branch `autose/issue-N`**, pushed only by the release job | This is what the PR and CI need, and nothing else. |
| Progress and pointers for humans | **One sticky comment** on the issue (found by an HTML marker), updated by the orchestrator: stage, check result, link to the run | Visible where the maintainer started the run; the reviewer never reads issue comments. |
| Reviewer verdict | **PR review** (body = `review.md`) and `review.json` artifact | Visible in the PR; the router reads the artifact, not the comment. |

Not used: see Alternatives considered.

**Restarts.** The build job uploads `.autose/out/` with `if: always()`, so a crashed attempt still
leaves its finished stages. "Re-run failed jobs" makes the orchestrator download the round's
`state.json`, skip stages whose check passed, and resume at the first unfinished stage. A new
trigger on the same issue starts a fresh run from stage 1 (maintainer comments added since are new
input), and the release job force-pushes the branch with lease, so a restart cannot interleave two
histories.

## Alternatives considered

- **Commit the artifacts on the PR branch** (`.autose/spec.md` etc.). Easy to read next to the code,
  but the reviewer's checkout would then contain the builders' reasoning, breaking ADR-008, and the
  PR diff would carry files a human reviewer does not want. Rejected.
- **The Actions cache.** Evictable and keyed for speed, not correctness; a missing entry would
  silently restart a stage. Rejected.
- **PR comments as the state store.** Readable, but the reviewer job reads the PR, and parsing state
  out of comments is fragile. Used only for the human-facing sticky status, never read back as state.
- **An external store (database, gist).** Another secret and another service to fail. Rejected.

## Consequences

- The PR diff contains only `markdown/**`, `docs/**` and `tests/**`, which is what a human reviewer
  expects to see.
- Artifacts expire after 90 days; `results/` in the submission repository keeps a copy of every
  artifact used in the report.
- Cross-run state is deliberately thin (branch + comment), so a stale state cannot poison a new run.
