# ADR-007: Stage checks are deterministic code; an LLM judge only advises on testability, and code makes the call

- **Decision area:** D7, checks
- **Status:** Superseded in part by [ADR-011](ADR-011.md) (2026-11-21): the stage-1 judge rule. Every
  other row of the check table below still holds.

## Context

Every stage must pass a check before handing over. A check run by the same agent that did the work
("I verified my tests pass") is not a check. Some properties are mechanical (does the file exist,
do the tests pass); one is semantic ("all acceptance criteria are testable").

## Decision

Each check is a function in `checks.py` that returns `pass/fail + reasons`. The orchestrator, not an
agent, calls it and decides.

| Stage | Check (deterministic unless marked) |
|---|---|
| 1 | Parse `spec.md` records (A1 record format). Each AC: unique `AC-` ID, `Given ... when ... then ...`, no A1 weak/vague word, linked to an FR. At least one Must FR is READY. **Judge** (`claude-haiku-5-5`, no tools, JSON schema): per AC, `testable: bool` + reason. Pass = lint clean **and** every READY AC judged testable. |
| 2 | Parse the change table of `design.md`. Each `modify` row: file exists, symbol found with `ast` (class, function or `Class.method`); `add` rows: path is under an allowed directory; every READY AC appears in some row; `docs/changelog.md` listed when `markdown/` changes. |
| 3 | Diff non-empty; paths allowed for the developer; `python -m compileall -q markdown`; `pip install -e .`; `python -c "import markdown; markdown.markdown('*x*')"`; `flake8` with the repo's `tox.ini` config on changed `.py` files. |
| 4 | New test ids contain each READY AC id; new tests **fail on the base commit** (at least one) and **pass on head**; full suite `python -m unittest discover tests` passes on head with no new failures or errors compared with the recorded baseline. |
| 5 | `gh pr view` shows the PR open; all check runs on head SHA `completed/success`. |
| 6 | `review.json` validates against the schema; `request_changes` must include ≥1 blocking finding with `file` and `evidence`; otherwise the verdict is downgraded to `comment` and logged. |

The judge in stage 1 is advisory: it can fail a check (an AC it calls untestable is sent back to
the analyst once), but it cannot pass one that the lint fails. Its prompt contains only the AC
text, not the issue, so it cannot be steered by issue content.

## Alternatives considered

- **LLM-as-judge for every stage.** Easy to write, but non-deterministic, gameable by the artifact
  it judges, and unnecessary where a test or a parser gives the answer.
- **Pure lint for stage 1.** A criterion can be well-formed and still untestable ("then the output
  is correct"). The judge catches those cheaply.
- **Agent self-report** (the tester writes "all tests pass"). Rejected; the orchestrator re-runs
  the suite itself.

## Consequences

- "Fail on base, pass on head" rejects tautological tests (tests that pass whatever the code
  does), which is the main way an agent fools a test gate.
- Stage 5 duplicates some of CI locally (flake8, suite, changelog row) so that CI failures are rare
  and the expensive release/CI round trip is not used as a debugger.
- Deterministic checks are only as good as their rules: a test that names an AC but asserts
  something weak still passes. The hidden tests and the reviewer are the backstop.
