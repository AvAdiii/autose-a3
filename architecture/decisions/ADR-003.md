# ADR-003: Hand-offs are whole artifacts, filtered by need-to-know; the tester works at the base commit

- **Decision area:** D3, hand-offs
- **Status:** Accepted (2026-11-21)

## Context

Every agent starts with an empty context. What it receives decides both quality (enough to do the
job) and independence (not so much that it inherits another agent's mistakes). Untrusted issue text
is also a prompt-injection vector (ADR-009), so the fewer agents that read it, the better.

Options per hand-off: the full upstream artifact, an LLM summary of it, the upstream agent's
transcript, or repository access only.

## Decision

Agents receive **full artifacts, never summaries or transcripts**, and only the ones they need:

| Agent | Receives | Withheld, and why |
|---|---|---|
| Analyst | issue title + body + maintainer-only comments (as quoted data), repository read access, A1 skill | non-maintainer comments (anyone can write them) |
| Architect | `spec.md`, `ARCHITECTURE.md`, repository | raw issue: the spec is the contract; if the spec lost something, the reviewer will see it against the issue |
| Developer | `spec.md`, `design.md`, repository; on retry the failing test ids + assertion text | raw issue (injection surface), tester's reasoning |
| Tester | `spec.md`, `design.md`, repository **checked out at the base commit** | the implementation: tests are written against the specified interface, not against the code they test |
| Reviewer | issue, PR diff, repository at PR head | spec, design, test report, PR body, transcripts (ADR-008) |

Rework inputs are the reviewer's blocking findings only (title, file, line, evidence, category),
never its full review text, so the builders fix the problem instead of arguing with the review.

The tester works in a `git worktree` at the base commit. It runs its tests there and they are
expected to fail (the feature does not exist yet). The orchestrator then copies only `tests/**` into
the head worktree and runs them. A test that cannot fail on the base commit does not test the change.

## Alternatives considered

- **Summaries between agents.** Cheaper context, but a summary is a lossy re-interpretation by a
  model, and errors in it cannot be traced to an artifact a human can read. Artifacts here are
  short (1-4 KB), so summarising saves almost nothing.
- **Shared transcript / one conversation.** Rejected: it is exactly the shared-assumption channel
  the separation is meant to remove.
- **Tester sees the implementation.** Easier for the tester (it can read real signatures), but the
  tests then describe what the code does rather than what the spec asks. Rejected; the price is
  that `design.md` must state the interface precisely, which the stage 2 check enforces.

## Consequences

- `design.md` becomes the interface contract between developer and tester. A vague design shows up
  quickly as tests that fail for interface reasons, which routes back to design (ADR-002).
- The untrusted issue text reaches two agents only, neither of which can push.
- Each artifact must be self-contained, which makes the GitHub trace readable by a maintainer.
