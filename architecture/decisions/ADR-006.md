# ADR-006: Sonnet for the builders, Opus for the reviewer, Haiku for the spec judge

- **Decision area:** D6, models
- **Status:** Accepted (2026-11-21); the reviewer choice is tested in experiment E2

## Context

All model access goes through one Claude subscription token (`CLAUDE_CODE_OAUTH_TOKEN`), so cost
shows up as usage against a rolling 5-hour quota rather than dollars, and a run that exhausts the
quota fails mid-stage. Available models: `claude-opus-5-5` (strongest, most quota per token),
`claude-sonnet-5-5` (strong coding, cheaper), `claude-haiku-5-5` (fast, cheapest). The tasks are
small Python changes in a 10 kLOC library with a sub-second test suite.

## Decision

| Role | Model | Reasoning |
|---|---|---|
| Analyst | `claude-sonnet-5-5` | The A1 skill is long and rule-heavy (tags, EARS, readiness gate); a small model is more likely to drop one of its rules, and a bad spec poisons every later stage. |
| Architect | `claude-sonnet-5-5` | Needs to map a spec onto the extension API correctly; mistakes here are expensive later. |
| Developer | `claude-sonnet-5-5` | Most tokens are spent here; Sonnet is the best quality per unit of quota for code edits. |
| Tester | `claude-sonnet-5-5` | Writing a test that fails on base and passes on a correct head is as hard as the code. |
| Spec judge | `claude-haiku-5-5` | Classification of 3-10 short sentences; no tools; runs every time stage 1 passes lint. |
| Reviewer | `claude-opus-5-5` | Reviews are few (≤3 per issue) and short in tokens, but a missed defect reaches the human. A **different model** from the builders also reduces correlated blind spots: the reviewer does not share the developer's exact failure modes. |

Models are pinned by full ID in `workflow/config.yml`, not by alias, so a silent model update cannot
change behaviour mid-experiment.

## Alternatives considered

- **Opus everywhere.** Best single-stage quality, but would spend roughly 5x the quota per run and
  hit the 5-hour limit after one or two issues. Rejected.
- **Haiku for developer/tester.** Cheapest, but test-fix loops multiply calls; a weaker developer
  costs more attempts. Not chosen without evidence; can be revisited.
- **A different vendor for the reviewer** (stronger independence argument). No other provider
  credential is available for this project; GitHub Models' free tier caps input at about 8k tokens
  per request, too small for an agent that reads a diff and runs tests. Recorded as a limitation.

## How this is tested

Experiment E2 runs the same independent reviewer with Opus and with Sonnet on the five seeded PRs
and compares defects caught, false rejections and tokens.

## Consequences

- One provider means one outage or quota exhaustion stops every stage; ADR-009 handles this as a
  clean stop with an explanation, not a retry loop.
- Model diversity is within one family only.
