# ADR-005: Agents get built-in Claude Code tools only, fenced per role by a PreToolUse hook; GitHub is reached only by deterministic code

- **Decision area:** D5, tools
- **Status:** Accepted (2026-11-21)

## Context

Agents need to read code, edit files and run tests. Something must also push, open PRs, comment
and post reviews. The options for GitHub access are the GitHub MCP server, the `gh` CLI or the REST
API; the question is *who* holds that access. Prompt-level instructions ("do not edit tests") are
not enforcement.

## Decision

1. **No agent has a GitHub tool or token.** All GitHub operations are made by Python (`gh` CLI)
   in the orchestrator, `release.py` and `review.py`. Agent subprocesses are started with an
   explicit environment that contains no `GITHUB_TOKEN`/`GH_TOKEN`, checkouts use
   `persist-credentials: false`, and `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1` keeps the model
   credential out of the agent's Bash subprocesses.
2. **Built-in tools only, chosen per role** with `--tools` (what exists) and `--allowedTools`
   (what runs without asking). No MCP servers (`--strict-mcp-config` with none), no `WebFetch`,
   `WebSearch` or `Task`.

   | Role | Tools | Write scope (guard) | Bash policy (guard) |
   |---|---|---|---|
   | Analyst | Read Grep Glob Write | `$OUT/spec.md` | n/a |
   | Architect | Read Grep Glob Write Bash | `$OUT/design.md` | read-only probes (`python -c`) to see today's output; the orchestrator resets the tree afterwards |
   | Developer | Read Grep Glob Edit Write Bash | `markdown/**`, `docs/**`, `pyproject.toml` | no `git` writes, no network tools, no package installs |
   | Tester | Read Grep Glob Edit Write Bash | `tests/**` | same |
   | Reviewer | Read Grep Glob Bash | none (no Edit/Write tool at all) | same; may run tests and scripts |
   | Spec judge | none | none | n/a |

3. **`guard.py` is a PreToolUse hook** loaded with `--settings`, with `--setting-sources ""` so
   no repository or user settings can override it. It reads the role from the environment, denies
   any Edit/Write outside the role's paths (after resolving `..` and symlinks), denies Bash commands
   matching the deny list, and logs every decision to `guard.log` (uploaded with the artifacts).
4. **The GitHub App `autose-dev-avadiii` has no `workflows` permission**, so even a compromised
   release step cannot push a change to `.github/workflows/`.
5. **Per-job `GITHUB_TOKEN` scopes** (workflow default `permissions: {}`):

   | Job | Scopes | Why |
   |---|---|---|
   | gate | contents:read, issues:write, pull-requests:read, actions:write | reaction + status comment; resolve PR → issue; re-dispatch a PR-comment run |
   | build | contents:read, issues:write | status comment, clarification questions; **no push** |
   | release | contents:read, checks:read, statuses:read, issues:write (+ App token: contents, pull-requests) | push and PR via the App only; read CI |
   | review | contents:read, pull-requests:write, issues:write | post the review and status after the agent exits; **no push** |

## Alternatives considered

- **GitHub MCP server for agents.** Convenient (agents could comment, open PRs), but it puts a
  write token next to untrusted text and makes "the reviewer cannot push" a matter of which MCP
  tools are listed. Rejected.
- **`gh` available to agents with a read-only token.** Lets the reviewer fetch PR metadata itself,
  but also the PR body and the issue thread, which ADR-008 withholds. Rejected; the review job
  hands it exactly the issue and diff.
- **Prompt-only restrictions.** Rejected: unenforceable and invisible in logs.

## Consequences

- Each restriction is enforced in a different layer (job permissions, missing credentials,
  `--tools`, hook, App permissions), so one mistake does not open everything.
- The guard's deny list is pattern-based and can be bypassed by a determined Bash command (e.g.
  writing a file through `python -c`). The real boundary for the developer and tester is that the
  orchestrator only keeps changes under their allowed paths (`checks.check_paths`) and that no
  credential exists to push with.
  Observed in the first real run ([44887224113](https://github.com/AvAdiii/markdown/actions/runs/44887224113)):
  the tester appended its test class with `cat >> tests/... <<'EOF'`, a write the Edit/Write rule
  never sees; it was inside `tests/**`, so the path filter kept it, as designed.
