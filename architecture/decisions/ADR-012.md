# ADR-012: Sonnet reviews by default; Opus stays available per run

- **Decision area:** D6, models (supersedes the reviewer row of [ADR-006](ADR-006.md))
- **Status:** Accepted (2026-11-21)

## Context

ADR-006 chose `claude-opus-5-5` for the reviewer: reviews are few and short, a missed defect reaches
the human, and a different model from the builders should reduce correlated blind spots. Experiment
E2 (`experiment/variants.md`) tested this on the five seeded PRs, and the rule for reading the
result was written down before the run: *if Sonnet matches Opus, ADR-006 is superseded.*

| Reviewer (isolated input) | Verdict right | Planted defect found | Routing right | False rejection | Own checks run (per PR) | Output tokens (5 reviews) | Agent time |
|---|---|---|---|---|---|---|---|
| `claude-opus-5-5` | 5/5 | 4/4 | 4/4 | 0/1 | 6, 5, 7, 7, 7 | 14,429 | 137 s |
| `claude-sonnet-5-5` | 5/5 | 4/4 | 4/4 | 0/1 | 3, 3, 5, 5, 3 | 8,435 | 80 s |

Sonnet matched Opus on every measure, at 58 % of the output tokens and 58 % of the time. It ran
fewer probes, but each was enough: every rejection carried a blocking finding with executed
evidence that named the planted defect (`results/reviews_scored.csv`). The binding constraint in
practice was the subscription quota, not the reviewer's accuracy. Two runs (R8, R9) were stopped by
the 5-hour limit.

## Decision

1. The default reviewer model is `claude-sonnet-5-5` (`config.json` `models.reviewer`).
2. `reviewer_model` stays a workflow input, so a maintainer can ask for an Opus review of a risky PR.
3. Everything else in ADR-008 stays. The reviewer is still isolated by job, VM, identity, prompt and
   input, and it still must execute a check to approve. Only "a different model from the builders"
   is given up.

## Alternatives considered

- **Keep Opus (ignore the pre-stated rule).** Defensible only on the model-diversity argument, which
  the data cannot test with five easy defects. Keeping it would make the experiment decorative.
- **Opus only on the last round.** Adds a model switch to the routing for no measured benefit.

## Consequences

- About 40 % less quota per review, which matters more than any accuracy gain this data could show.
- The result is a ceiling effect: all three reviewer cells scored 5/5. The seeded defects are found
  by running the issue's own examples, and both models did that. Harder, subtler defects might
  separate the models, so this decision should be revisited when such a set exists (Limitations).
- Builder and reviewer now share a model family and size, so correlated blind spots are possible.
  The isolation of input (no spec, design or test report) is the remaining guard against them.
- All pipeline runs R0–R10 used the Opus reviewer. The change applies from harness PR #23 on.
