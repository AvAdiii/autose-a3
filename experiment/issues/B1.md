title: "fenced_code + attr_list: `linenums` on a code block crashes with TypeError unless codehilite is enabled"
---
I use `fenced_code` together with `attr_list` and turned off `codehilite` because we highlight on the client with highlight.js. Some of our older docs still have `linenums` on their fenced blocks from when we used Pygments, and now the build blows up on them.

Minimal example:

```python
import markdown

src = "``` { .python linenums }\nprint(1)\n```"
markdown.markdown(src, extensions=["fenced_code", "attr_list"])
```

```
Traceback (most recent call last):
  ...
TypeError: cannot serialize None (type NoneType)
```

`linenums="true"` gives `TypeError: cannot serialize True (type bool)` instead. Same story with `guess_lang` and `noclasses`. Something like `data-x="1"` works fine, and if I add `codehilite` to the extensions everything renders.

I'd expect the block to just render as a normal code block when codehilite isn't there, instead of the whole conversion failing. One stray attribute shouldn't take down the page.

Markdown 3.x (current main), Python 3.12, Linux.
